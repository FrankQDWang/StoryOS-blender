# 创建与开书长帧优化

2026-10-13 · 基线 main `f4979f7` · 分支 `codex/interaction-stalls`

## 实现与实测

保持模型、材质参数、光照效果、帧率策略、动画公式和交互流程。仅改变 GPU 资源准备时机与创建光源的生命周期。

| 场景 | 基线最大帧间隔，三轮 ms | 最终候选，三轮 ms | 中位数降幅 |
|---|---|---|---|
| 开书 | 83.4 / 100 / 116.6 | 33.4 / 16.8 / 33.3 | 66.7% |
| 创建 | 283.3 / 233.4 / 233.4 | 16.8 / 16.8 / 16.8 | 92.8% |

最终交替配对数据：`final-pairs/summary.json`。Chrome、Apple M4 Metal、1512×695、设备 DPR2（应用上限1.5）、隔离五书、生产构建。不开 CPU profiler 或 GPU 查询。候选六个动作窗口均无50ms长任务、无页面错误。基线每个动作窗口均复现长任务。样本是本机窗口测量，不承诺所有机器的最大延迟。

此次执行启动时脚本仍把基线失败也计入进程退出码，因此 final-pairs 命令退出1；候选六窗口全部通过。当前脚本已修为配对模式只以候选决定退出码，所有基线失败继续保存；未重采或覆盖数据。

### 原因与修改

- 创建：条件挂载点光源改变全场景光源数量，触发shader变体编译。CPU profile主要热点是getProgramInfoLog。保持这盏光源挂载；非创建状态强度0，创建期间沿原书本轨迹、原颜色/亮度移动。三轮原始验证在 `light/`。
- 开书：手部GLB已预加载，但普通纹理、材质程序、几何和变形纹理在首次显示才准备。`PrepareOpening` 在首屏后分批上传现有纹理，异步编译，并在独立场景中作一次1×1离屏绘制；使用灯光副本，保留并恢复渲染目标与阴影更新状态。实际手部模型、骨骼、动作与书本变形函数不改。
- 只预编译和上传普通纹理还剩67–83ms长帧，见 `candidate/`；加入离屏几何准备后消除该动作长任务，见 `warm/`。
- 初版离屏绘制复用了整个房间，固定时刻对照发现炉火附近26个颜色通道超过阈值。收窄到独立手部场景后，此帧逐像素一致。失败样本完整保留，没有调宽阈值。

## 验证状态

- 现有17项测试通过；最终正式构建通过。
- 鼠标冒烟检查真实pointer lock、可信buttons=0鼠标移动、相机旋转、WASD、Esc退出全景及再次进入；之后走开书/返回、删除、创建入空位、Quick Access。
- `denied-lock/`：注入拒绝锁定，脚本按预期失败。拖拽回退不会误算通过。
- `final-smoke/`：有界面自动化点击未取得锁定，严格报失败；不得把该结果描述成原生Chrome验收通过。用户要求停止抢占桌面后，原生验收保持未完成，见 `native-check.md`。
- 原粒子随机种子与对象UUID共用序列，新增预热对象会改变粒子随机位置。`capture.mjs` 现在保存并回放真实Sparkles的属性作为一致输入，保留全部粒子数量、材质、动画。原始差异在 `visual-*`，输入控制后的结果在 `controlled-*`，最终11个状态全部逐像素一致，见 `final-visual.json`。
- 原始 `baseline/` 首次诊断曾与另一浏览器冒烟重叠并中断，不用于最终收益数字。`*-profile/` 是有Profiler的诊断样本；只用final-pairs作为性能结论。

## 复现

构建探针版：`node tools/idle-render-cost/build.mjs <label>`，服务：`node tools/idle-render-cost/serve.mjs <label> <port>`。基线应在f4979f7完整源码上构建，候选按本分支构建。

`node tools/idle-render-cost/stalls.mjs <out> <baseline-url> <candidate-url>` 会交替执行三轮，候选任何动作窗口超过50ms或发生页面错误则失败。测量时一次只运行一个浏览器流程。

正常生产预览为 `http://127.0.0.1:4405/preview.html`。此入口只在新端口没有书库时放入五书演示，随后跳回正常应用；使用正式构建，无Probe和原生诊断标记，不改既有4173或其他端口作品。
