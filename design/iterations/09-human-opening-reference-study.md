# 开书动作调研：先确定抓法，再调整关节

2026-09-17。针对用户对 `comparison-wrist.jpg` 的反馈：“比上一版好了”，但上面那只手“绝对不是人类的动作”，随后明确要求“多做一些调研”。本轮补充真人视频、动作数据和制作方法研究；**运行模型及动画没有继续修改，preview.3 的手部自然度仍未通过。**

## 结论先行

上一轮把前臂接得更直，却保留了有问题的抓法。当前应先重做**右手从书的外侧夹住封面、抬起时掌面如何转动**，而不是继续优化前臂—手掌夹角的数值。

建议保留现有免费 CC0 手模型及“左手支撑、右手打开”的分工。采用下方 R5 的侧边夹持作为下一次姿态实验的主要参考；先检查抓稳、半开、近竖直三个关键姿势，再处理插值。R5 是真人参考，不是可直接复制到当前巨型厚封面的动画；它同时带起了部分纸页，也没有当前斜书台，不能照搬轨迹。

## 与当前实现对应的问题

1. **抓取方向不适合当前呈现。** 当前右手从右下角伸向前方，四指在外封面，拇指探向底边；封面竖起后，同一手形变成侧向、细长的钩子。R5 从外侧夹入，拇指和弯曲指组分处两侧，翻转时逐渐变成扶内页的姿势。不能只把当前手腕再摆直。
2. **手形被固定太久。** `pose()` 的握紧值在0.78–1.76秒恒定，右腕朝向直接随封面角度旋转。读源模型在0.80/1.30/1.70秒的骨骼采样也显示：去掉手腕整体变换后，各指节位置相同到记录精度。也就是说，这段的主要变化真的是把同一手形整体搬动、旋转，不是抓取过程中重新组织手指。证据：`current-grip-probe.json`，只读脚本 `probe-grip.py`。
3. **拇指和指组的关系读不清。** 画面中拇指横撑、四指向上，缺少明确、紧凑的夹边关系。参考并不支持“所有手指都要用力弯曲”；需要食指/中指承担主要接触，其余手指有自然层次，而不是把五根手指统一握紧。
4. **前臂好看不等于身体能完成动作。** 当前所谓 `elbow` 只是决定前臂方向的辅助位置，没有肩—上臂—肘链。上一轮抬高它能减轻折角，但会让右臂在画面左侧直立，仍需用完整手臂的方向关系判断。不能只用45°回归界限验收人体姿态。
5. **比例是适配条件。** 源书封面尺寸为0.78×1.0×0.065项目单位，厚度约为高度的6.5%；当前手腕到中指末端约0.22单位。它是巨型厚封面道具。R5 是较薄、手持的书，不能按照片里的开口大小直接捏合，否则可能穿插。此处记录原因，不是建议现在修改已认可的房间或书。

其中1、3、4是结合画面与代码的诊断；不是已证明某个关节违反生理限值。2和5是可从当前文件复查的实现事实。

## 免费动作与制作路线

完整核查见[真实动作数据研究](../reference-library/ready-made-hands/real-motion-data-research.md)。本轮未找到已经验证能够直接进入公开仓库的免费 Blender 手书完整动画。ARCTIC 确有 Notebook 与双手/铰链时序，但其[数据许可](https://arctic.is.tue.mpg.de/license.html)不允许直接再分发；不能把网站页脚的 CC 标识当数据许可。OakInk2、GigaHands 各有候选价值，也各有未核实片段、许可或适配边界，不能宣布“现成方案已经找到”。

当前成本最低且结果最可控的路线仍是：**现有 CC0 手形 + 真人参考指导的姿态制作 + 离线烘焙**。改进重点不在换更贵皮肤，也不在加网页实时物理。

[Animation Mentor 的制作指导，印刷页38–39、43–44](https://content.animationmentor.com/pdfs/AnimationMentor_TipsTricks_EveryAnimator.pdf)强调手部姿态、肩部参与和事先明确关键姿势，再进入动画制作。这里采用其工作方法，不把专家文章当本片段已经自然的证明。[Blender 官方动画工具](https://www.blender.org/features/animation/)提供 FK/IK、约束与可动画的约束权重，可在制作阶段明确指端接触与释放；工具存在不保证自动得到真人动作。

## 下一次小步实验的明确范围

- 保留模型、书、房间、火焰、左右手分工与3.5秒流程；只试右手的**侧边抓取与抬起姿态**。先建立三个可单独观察的姿势：抓稳、半开、接近竖直。
- 从 R5 的拇指外侧、弯曲指组内侧关系开始，按当前厚封面适配接触点。指端接触应先确定，再决定掌面和腕的位置；不能让整手直接继承封面角度后补肘点。
- 在制作场景中核对肩/肘方向及前臂长度，避免“右手从左侧长出来”的阅读错觉；是否需要补制作控制骨骼由实验决定，不先添加网页运行时系统。
- 三姿势分别看主视角与能看到接触的侧面。接触清楚、手形无明显钩状后，再生成其间动作，并在 Chrome 正常速度、慢放及真实入口检查；五书位复核在局部通过之后。
- 本次尚未执行上述实验。松手后抓空气、撤手节奏、自动翻页、漫游身体仍是后续问题；不把参考研究本身写成已改进动画。
